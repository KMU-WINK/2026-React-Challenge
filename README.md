# 1주차 키워드 정리

## Figma의 Auto Layout은 무엇이고 CSS Flexbox와 어떻게 대응되나요?

Auto Layout은 방향, 간격, 여백만 정해두면 요소들을 알아서 정렬해주는 Figma 기능임. 방향은 `flex-direction`, 간격은 `gap`, 정렬은 `justify-content`/`align-items`로 거의 그대로 옮겨진다.

## Tailwind CSS와 일반 CSS 또는 CSS Modules의 장단점은 무엇인가요?

Tailwind CSS는 클래스 이름 고민 없이 바로 스타일을 줄 수 있고 토큰 덕분에 값이 통일됨. 대신 클래스가 길어지면 읽기 힘들다. 일반 CSS는 익숙하지만 이름이 겹칠 수 있고, CSS Modules는 그 충돌은 막아주지만 이름 짓고 파일을 왔다 갔다 하는 건 그대로다.

## Tailwind v3와 v4의 설정 방식은 무엇이 다른가요?

v3는 `tailwind.config.js`에서 설정했는데, v4는 CSS 안의 `@theme`에서 바로 설정함. `@theme`에 넣은 값은 CSS 변수가 돼서 `var(--color-primary)`처럼 일반 CSS에서도 쓸 수 있다.

# 2주차 키워드 정리

## State 끌어올리기(Lifting State Up)란 무엇이고 왜 필요한가요?

여러 컴포넌트가 같은 State를 써야 할 때, 그 State를 공통 부모로 옮기고 Props로 내려주는 것. 좋아요 State가 `PostCard` 안에만 있으면 부모인 `PostList`는 그 값을 몰라서 피드 상단에 "좋아요한 게시글 개수"를 보여줄 수 없다. 그래서 State를 위로 올려야 한다.

## React가 Virtual DOM을 사용하는 이유는 무엇인가요?

실제 DOM을 자주 직접 고치면 화면을 다시 그리는 작업이 많아 느려진다. React는 가상의 DOM에서 바뀌기 전후를 비교해 달라진 부분만 실제 DOM에 반영해서 효율적으로 화면을 업데이트한다.

## SPA와 MPA의 차이는 무엇인가요?

MPA는 페이지를 이동할 때마다 서버에서 새 HTML을 받아와 새로고침이 일어난다. SPA는 처음 한 번만 페이지를 받고 이후엔 필요한 부분만 바꿔서 보여준다. `<Link>`로 이동했을 때 새로고침 없이 화면만 바뀐 게 SPA 방식이다.
